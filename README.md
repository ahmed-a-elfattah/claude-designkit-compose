# Claude Design Importer

Android Studio plugin that turns a Claude Design export (zip or folder) into a Compose design system in your module:

- `Color.kt`, `Type.kt`, `Shape.kt`, `Spacing.kt`, `Elevation.kt`, `Theme.kt` with `AppTheme { }` and `AppTheme.colors/typography/shapes/spacing/elevation`, mapped onto `MaterialTheme`. Dark values come from `[data-theme=dark]`, `.dark`, `prefers-color-scheme: dark` or a `dark` token group.
- `AppIcons`, one entry point for every icon. If the design uses an icon Material already has (same shape, or same name such as `arrow-left` → `ArrowBack`), the plugin references the Material icon instead of copying it. Other icons become `ImageVector` files or `res/drawable` XML. Preference is given to `material-icons-core`, and the plugin adds the needed dependency to your build/version catalog.
- `components/`: `AppButton`, `AppTextField`, `AppCard`, `AppChip`, with variants taken from `.btn-*`, `.card`, `.input` and `.badge-*` CSS rules or a `components.json`, plus `@Preview`s.

The plugin reads Claude Design exports: `ds/<name>/tokens.json` with light/dark colors, the type scale, spacing, radius, shadow and size tokens, whose `usage` notes become KDoc. It also reads the CSS component classes (prefixed classes like `.pf-btn.primary` and status classes like `.b-pending` become `AppBadge` variants) and the Material Symbols names used in the `.dc.html` artboard, which map to Compose Material icons by exact name.

It also reads W3C/Tokens Studio JSON tokens, CSS custom properties (including `oklch()` and shadcn-style `hsl` triplets), SVG icons and sprites, and TTF/OTF fonts.

Generated theme: `AppTheme.colors / typography / shapes / spacing / elevation / sizes`.

Localization: bilingual text in the prototype, both `L('Back', 'رجوع')` calls and `{ en: …, ar: … }` objects, is added to the module's `res/values/strings.xml` and `res/values-ar/strings.xml`. The importer creates `values-ar/strings.xml` if it's missing. The strings go inside a marked `Claude Design Importer: begin … end` block: a re-import replaces only that block and never touches your own entries, and turning strings off removes the block. Text the prototype joins with a value becomes a format string (`"Refund · %1$s"`). A key that the module already declares, or that is a Java keyword, gets a `_text` suffix. You can untick individual strings in the import dialog's Strings tab.

## Use it

1. `./gradlew :plugin:buildPlugin`, then in Android Studio go to Settings › Plugins › ⚙ › Install Plugin from Disk… and pick `plugin/build/distributions/plugin-0.1.0.zip`.
2. Choose Tools › Import Claude Design System… and select the export.
3. In the preview, pick the module, package, prefix and icon format, and untick any name-matched Material icon that doesn't look right. Then click Import. Use Re-import later after you change the design.

Generated files carry a `Generated by Claude Design Importer` header, and `.claude-design-import` in the module lists them. A re-import only touches those files and removes icons you deleted from the design. Hand-written files at the same path are never overwritten.

## Without the IDE

```
./gradlew :tools:generate -Pexport=/path/export.zip -Pmodule=/path/app -Ppackage=com.example.app.designsystem -Pnamespace=com.example.app [-PiconFormat=DRAWABLE]
```

## Develop

- `./gradlew :core:test` runs the unit tests (fixture in `core/src/test/resources/fixture-export`).
- `./gradlew :plugin:runIde -PopenProject=/path/to/android/project` starts a sandbox Android Studio with the plugin.
- `./gradlew :tools:buildMaterialIndex` regenerates the Material icon geometry index.
- Requires `JAVA_HOME` pointing at a JDK 25 (Android Studio's: `/Applications/Android Studio.app/Contents/jbr/Contents/Home`). `androidStudioPath` in `gradle.properties` selects the IDE to build against.
- Readers live in `core/src/main/kotlin/dev/designimporter/core/reader/`. When a real Claude Design export differs from what they expect, adjust them there.
